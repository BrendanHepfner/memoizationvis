Memoized recursion: start at n−1, or start at 0?

Many counting problems can be written as memoized recursion in two directions. Starting at n−1 (the end), the function asks “how many ways get here from the start?” and recurses back toward 0. Starting at 0, it asks “how many ways get from here to the end?” and recurses forward toward n−1. Both cache every answer and always agree on the result. Which one does less work depends on the problem: pick an example below and watch both run in lockstep.

So which end should you start from?

      
What gets explored. Starting at n−1 only ever visits states that can reach the end, so it wastes work on states the start can’t reach. Starting at 0 only visits states the start can reach, so it wastes work on dead ends that never get to the end. Start from the side whose neighbourhood has fewer places that go nowhere. If a problem fails fast at one end, start there.

      
What the cache can answer later. Every cached number is measured from the base case. Starting at n−1 puts the base case at the start, so the cache survives a new goal. Starting at 0 puts it at the end, so the cache survives a new start. If you’ll ask many questions, put the base case at the end that stays fixed.

      
When neither matters. If every state can both be reached from the start and reach the end, the two directions do exactly the same work in a different order.
